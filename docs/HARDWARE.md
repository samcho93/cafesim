# M400 하드웨어 제어 요소 분석

원본 키오스크 앱(Electron, `hunik-solution`)의 소스에서 찾아낸 하드웨어 제어 요소입니다.
시뮬레이터의 장치 모델은 이 분석을 그대로 따릅니다. 바이트 단위 상세는 [PROTOCOL.md](PROTOCOL.md)에 있습니다.

## 장치와 연결

| 장치 | 연결 | 원본 소스 |
|---|---|---|
| 메인보드 (커피·온수·파우더·에이드 제조) | COM1, 38400 | `controller/serial/mainDevice/*`, `common/sequenceFunc.js`, `common/tagListV3.js` |
| 컵 디스펜서 | COM3, 9600 | `controller/serial/cup/*` |
| 제빙기 | COM2, 9600 | `controller/serial/ice/*` |
| 카드 단말기 (KSCAT) | HTTP 127.0.0.1:27098 (+ 단말 COM6) | `controller/pay/payTest.js` |
| 음성 안내 | `resources/sounds/*.mp3` | `model/soundManager.js` |

## 메뉴 시퀀스 (원본 S203~S206)

```
S203 1번 투출구 커피+온수 : 브로멕 상 → 불림 → 커피 추출 → 온수 추출 → 브로멕 하 → 브로멕 중
S204 1번 투출구 커피 샷   : 브로멕 상 → 불림 → 커피 추출 → 브로멕 하 → 브로멕 중
S205 2번 투출구 커피+온수 : S155 선택 → 브로멕 상 → 불림 → 커피 → 에이드1(온수) → 브로멕 하 → 중 → S155 해제
S206 2번 투출구 커피 샷
```

앞에는 그라인더 분쇄(S150/S171)와 레시피 60바이트 쓰기(S080~), 뒤에는 Clear15/Clear05가 붙습니다.

## 한 잔 제조 흐름 (원본 `serialRequestDrinks.js`)

1. 컵 디스펜서: 메뉴모드 → S001(ICE)/S002(HOT) = 1 → M017/M018 == '2' 대기 → 0
2. 제빙기 (아이스): B0 얼음/물 시간 → CF 폴링, D2 bit4 == 0 이 될 때까지 대기 (고객이 컵으로 레버를 눌러야 출빙)
3. 메인보드: 메뉴모드 → 투출구 램프 깜빡임 → S007=1, 컵 센서 감지 대기 → 램프 켬
4. 레시피 쓰기 → 시퀀스 실행 (각 명령 '1' → M == '2' 대기) → Clear
5. 램프 깜빡임 → S007=0, 컵 이탈 대기 → 램프 끔

## 원본 코드에서 발견한 주의점

- `setCupSensor()`가 주소를 `'007'`(3글자)로 보냅니다. 실기는 S007로 처리하므로 시뮬레이터도 같은 동작을 합니다.
- 메인보드 ACK는 12바이트, 컵 디스펜서 ACK는 10바이트입니다. 수신부가 길이를 세는 방식이 달라서, 이를 틀리면 컵 디스펜서 쪽이 무한 재전송합니다.
- `sendRequestWithChecksum` / `waitResponse`는 타임아웃 없이 무한 재시도합니다. 시뮬레이터의 **장애 주입**으로 이 동작을 재현할 수 있습니다.
- 원본 저장소의 `package.json`과 `dev_token.txt`에 GitHub 토큰이 평문으로 들어 있습니다. 폐기하고 다시 발급하는 것을 권장합니다.
