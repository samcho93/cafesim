# 원본 키오스크 기능 ↔ 시뮬레이터 확인 방법

원본 키오스크 앱(Electron)의 기능은 **두 가지 방법**으로 확인할 수 있습니다.

| 방법 | 설명 |
|---|---|
| **A. 원본 앱 그대로 실행** | `npm run kiosk:legacy`. 원본 소스(`source/`)를 수정하지 않고 가상 하드웨어 + **가상 메일빈 서버**에 연결합니다. 메뉴·설정·결제 기록·원격 명령이 모두 가상 서버로 가므로 실제 매장 데이터에 영향이 없습니다. |
| **B. 웹 키오스크 (3D 화면의 터치스크린)** | 원본 앱의 화면 흐름과 장비 제어 로직(`euro()`/`makeDrinks()`/세척/재고)을 웹으로 옮긴 버전입니다. 브라우저·GitHub Pages·Cloudflare 어디서나 실행됩니다. |

메뉴·매장·장비 설정은 실제 서버 역할을 하는 **관리 콘솔**(뷰어 상단 `⚙ 관리 콘솔`)에서 바꾸고, 두 키오스크 모두 그 데이터를 받아 동작합니다.

## 원본 앱을 가상 서버로 실행할 때 바뀌는 점

`tools/legacy-kiosk/main-hook.cjs`가 실행 중에만 다음을 바꿉니다 (소스 수정 없음).

- `serialport` → 시뮬레이터 TCP (COM1/2/3)
- `*.mailbean.kr` → 가상 메일빈 서버 (메인 프로세스·렌더러의 `node-fetch`, EventSource, 이미지)
- 카카오 알림톡 API → 가상 서버 로그 (실제 메시지 발송 없음)
- `shutdown`(원격 재부팅) 차단, `tasklist`는 KSCAT 에이전트가 있는 것으로 응답 (시뮬레이터가 27098 포트를 에뮬레이트)
- 창 모드, 자동 업데이트·작업표시줄 숨김 끔

실제 메일빈 서버를 쓰려면 `npm run kiosk:legacy -- --real --mac <장비 ID> --web stg`.

## 데이터 주의점 (원본 앱 기준)

- 카테고리 이름에는 `/ . #` 같은 특수문자를 쓸 수 없습니다. 원본 앱이 카테고리 이름으로 jQuery 선택자를 만들기 때문에 화면 구성 전체가 실패합니다. 관리 콘솔이 저장할 때 검사합니다.
- 메뉴 이름이 같은 상품이 둘 있으면 원본 앱은 이름으로 레시피를 찾기 때문에 앞의 것만 사용합니다.
- 원본 앱의 메뉴 관리 화면은 저장 기능이 없습니다 (서버에서만 편집). 시뮬레이터의 관리 콘솔이 그 역할을 합니다.
